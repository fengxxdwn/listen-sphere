# ListenSphere P9：无线链路恢复与采集兼容

## 已完成

- Android 控制与 UDP 传输发生网络类异常时，按 1、2、4、8、12、15 秒进行最多六次有界重连。
- 重连期间保持 AudioRecord 与 MediaProjection 采集会话，重连成功后使用主控端新下发的会话密钥和流编号恢复发送。
- Controller 的“断开连接”会先发送带原因的 Disconnect 控制消息；Android 将其视为用户操作并停止，不会自动连回。
- Controller 的“撤销信任”同样发送明确原因，设备必须重新配对。
- 麦克风和系统播放捕获优先使用 48 kHz Float32；初始化失败时自动回退为 48 kHz PCM16，并在发送前无分配转换为 Float32 双声道帧。
- Android 状态卡显示实际采集格式。

## 自动验证

- Android JVM 测试 4/4 通过，新增 PCM16 全幅值边界转换测试。
- Android Debug APK 构建通过。
- Windows Release 构建零警告、零错误，39/39 测试通过。

## 已知边界

- 自动重连复用开始发送时选定的 IP 和端口。若 Controller 重启后动态端口变化，需要返回主页面刷新设备并重新开始。
- MediaProjection 被系统或用户撤销属于不可恢复错误，需要重新授权。
- 蓝牙与 USB 当前只有模式入口和模块边界，实际音频传输尚未实现。
- `0.1.6-p9.1` 修复多网卡地址选择：Controller 的 mDNS 仅在具有 RFC1918/IPv6 本地地址的活动以太网或 WLAN 接口上公告，Android 自动发现也拒绝非本地地址。Radmin VPN、ToDesk 等虚拟公网段不会再覆盖真实 Wi-Fi 地址；手动连接仍允许用户自行指定其他地址。

## 人工验收

1. 无线发送中关闭手机 Wi-Fi 5–10 秒后恢复，确认页面显示自动重连并恢复电平与声音。
2. 在 Controller 远程声道点击“断开连接”，确认手机停止发送且不会自动连回；再次点击手机“开始发送”应无需验证码。
3. 在 Controller 撤销信任，确认手机停止；再次连接必须输入新验证码。
4. 连续执行三次网络中断恢复，检查无重复声道、无持续高 CPU、无 MediaProjection 重复授权弹窗。
