# ListenSphere P4 实施状态与验收

## 范围

P4 建立第一条可工作的局域网 PCM 音频链路：

`WASAPI Loopback → 48 kHz Float32 双声道 10 ms → 分片 → AES-GCM → UDP → 校验 → 重组 → 30 ms 抖动缓冲 → WASAPI 输出`

## 已实现

- Controller 启动双栈 UDP 接收端口，并仅通过已认证 TLS 1.3 控制连接下发音频会话。
- 每次控制连接生成新的 SessionId、StreamId、256 位随机密钥和 4 字节随机 salt。
- Sender 将一个 3,840 字节 PCM 帧拆为 4 个最大 1,200 字节的数据报。
- 每个分片独立使用 AES-256-GCM；固定 60 字节包头作为 AAD。
- 收包顺序为长度/格式/会话检查、AEAD 认证、重复包检查、帧重组、抖动缓冲。
- 重组窗口为 200 ms；过期残帧丢弃。
- 抖动缓冲目标为 3 帧（30 ms）；确认缺帧后插入 10 ms 等长静音。
- UDP 输出使用有界通道，慢播放端不会导致内存无限增长。
- Sender 显示发送帧、数据报和失败计数；Controller 显示接收、认证失败和隐蔽帧统计。
- Controller 自动选择默认 Windows 播放端点；无设备时仍接收并丢弃输出帧。

## 安全与实时约束

- mDNS/TXT 不包含音频密钥、证书指纹或 UDP 会话信息。
- 未知会话、错误来源 IP、认证失败、重复包和格式不匹配均不进入播放队列。
- 重复序号只在 AEAD 认证成功后登记，避免未认证包抢占合法序号。
- 音频密钥仅保存在内存；会话结束时使用零填充清理密钥数组。
- PacketSequence 即将回绕时发送器停止该会话，必须重新协商密钥，禁止 AES-GCM nonce 复用。
- P4 不在日志中记录 PCM、密钥、验证码或完整证书。

## 自动验证

- Release 构建必须为零警告、零错误。
- TLS 测试验证音频会话只在配对/固定证书成功后下发。
- 真实本机 UDP Socket 测试覆盖 4 个连续 PCM 帧的加密、16 个数据报发送、解密、重组和抖动输出。
- 抖动缓冲测试覆盖缺失 FrameSequence 时插入静音并恢复后续帧。
- 原有 P0–P3 测试必须全部回归。

## 延期人工验收

由于当前环境无法进行双电脑测试，以下项目延期但不删除：

1. 两台电脑同一专用网络下完成发现、配对和自动重连。
2. Sender 选择输出设备并开始捕获，Controller 应从选定输出端点播放同一内容。
3. 连续运行 10 分钟，记录发送/接收数据报、认证失败、隐蔽帧和主观卡顿。
4. 暂停播放、恢复播放、停止/重启捕获各 20 次。
5. 临时断网并恢复，确认旧 UDP 会话失效且重连生成新 SessionId/密钥。
6. 篡改或使用旧会话数据报，确认认证失败且无声音输出。

同机人工试听只建议在 Sender 捕获端点与 Controller 默认播放端点不同的情况下进行，否则可能形成回授。自动测试不依赖第二台电脑或真实扬声器。

## 当前边界

- 仅支持一条 48 kHz Float32 双声道 PCM 流和 10 ms 帧。
- 尚未实现多个 Sender 混音、独立远程音量、时钟漂移估计、自适应抖动缓冲和 Opus。
- UDP NAT 穿透、互联网中继和公网场景不属于当前范围。
