# 阶段 5：Android 与三模一致性

## 目标

统一无线网络、蓝牙和有线模式的操作体验、设备身份、连接状态、格式协商与恢复行为。

## 第一批：状态恢复与配置迁移

- 连接模式、音源、已选无线主控端、已选蓝牙电脑、手动地址和端口均持久化。
- USB 兼容模式、蓝牙编码格式和单/双声道选择均持久化。
- 配置采用独立 schema 版本；未知或已移除的枚举值安全回退，不阻止应用启动。
- Android 版本升级到 `0.5.0-stage5`（versionCode 24）。
- 应用从后台或系统设置返回时，立即刷新网络发现、蓝牙权限/开关/配对设备和 USB 状态。

## 已确认的既有能力

- 三种连接方式拥有统一入口，并共享声音来源和开始/停止操作。
- Wi-Fi、蓝牙和 USB 都使用 ListenSphere Protocol 身份；Controller 按设备 UUID 合并记录。
- Controller 主动断开后，Android 会停止本次任务而不是自动抢连。
- 蓝牙只允许选择手机编码、Controller 解码和 ListenSphere 已实现链路的交集。
- PCM16、IMA ADPCM 和 AAC-LC 支持协商；单声道与双声道均可选择。
- SBC、LDAC 等应用不可调用或链路未实现的格式保持不可选，并显示具体原因。

## 后续批次

- 自动开发批次已全部完成；剩余工作为最终真机人工验收。

## 第二批：统一 Controller 身份

- Windows 蓝牙能力探测响应增加稳定的 Controller UUID。
- 扩展字段使用响应标志位，并只追加到探测响应末尾；旧 Android 客户端会安全忽略，
  既有音频流握手布局保持不变。
- Android 使用与 Protobuf 相同的 .NET Guid 字节序读取 UUID。
- 蓝牙 MAC 与 Controller UUID 的关联持久化，应用重启后仍能识别同一台电脑。
- 无线发现和蓝牙设备具有同一 UUID 时，在两个模式间同步目标选择。
- 蓝牙卡片显示“已关联”及无线发现名称，避免把同一台电脑误认为两个主控端。
- 新旧两种蓝牙探测响应均有固定二进制兼容测试。

## 第二批人工验收

1. 同时开启电脑 Wi-Fi 和蓝牙，并确保手机能通过 Wi-Fi 发现该 Controller。
2. 切换到蓝牙，选择同一台电脑并点击“测试蓝牙连接”。
3. 能力检测完成后，蓝牙卡片应显示“已关联”及无线模式下的 Controller 名称。
4. 返回无线网络模式，确认对应 Controller 自动保持选中。
5. 完全退出并重新打开 Android 应用，再进入蓝牙模式，确认关联仍然存在。
6. 临时关闭 Wi-Fi 后重新进入蓝牙模式，确认已记录的蓝牙设备仍可选择和连接。

## 第三批：统一连接体验

- Wi-Fi、蓝牙和 USB 共用错误分类器，不再把 socket、厂商错误码或异常类型直接展示给用户。
- 权限缺失、连接超时、主控无响应、身份变化、主控主动断开和未知错误均提供对应中文建议。
- 网络和蓝牙自动重连期间显示相同结构的恢复建议与下一次尝试时间。
- 每种连接方式保留最近一次成功的 Controller 名称和连接时间。
- 最新成功的连接方式在三模选择卡片上标记为“最近使用”。
- 主页面集中显示最多三条最近成功记录，三模切换不会相互覆盖。
- 只有真正进入 Streaming 状态才写入历史，失败尝试和能力探测不会伪造成功记录。

## 第四批：后台、权限与升级恢复

- 主页面新增“后台与权限”状态卡，实时检查麦克风、附近设备、通知和电池优化状态。
- 权限未允许时提供当前应用的系统设置入口，支持永久拒绝后的人工恢复。
- 电池受限时提供系统电池优化入口，不自动申请豁免或绕过 Android 限制。
- 从系统设置返回时立即刷新权限、蓝牙、网络发现和 USB 状态。
- 配置 schema 升级到 v2，覆盖安装时保留模式、音源、地址、编码、声道、历史和设备关联。
- Android 更新为 `0.5.1-stage5`（versionCode 25）。
- 禁止 Android 云备份设备身份与信任数据，避免跨设备恢复失效的密钥关系。
- 进程被系统回收后恢复界面配置，但不自动恢复麦克风或屏幕音频采集。
- 完整真机矩阵见 `docs/testing/stage5-android-final-acceptance.md`。
