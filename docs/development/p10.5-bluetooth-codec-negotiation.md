# P10.5 蓝牙音频格式协商

## 已完成

- Bluetooth RFCOMM 握手公布主控端的编解码格式与声道能力位图。
- Android 读取 `MediaCodecList`，检测应用可调用的 AAC、SBC、LDAC 编码器，并标记是否为硬件加速。
- 界面只允许选择“手机编码能力、主控解码能力、ListenSphere 链路实现”三者的交集。
- PCM16 和 IMA ADPCM 均支持 48 kHz、10 ms、单声道或双声道传输。
- AAC-LC 使用 Android `MediaCodec` 生成 48 kHz ADTS 帧；双声道 160 kbps，
  单声道 96 kbps，并由 Windows Media Foundation 解码。
- AAC 的 1024 采样编码帧会在主控端重新切分为混音器使用的 480 采样块。
- 双声道 IMA ADPCM 使用两个独立声道块，主控解码后保持左右声道顺序。
- 会话状态显示实际协商的编码格式与声道数。

## 当前可用格式

| 格式 | 手机编码 | Windows 主控解码 | RFCOMM 链路 | 当前状态 |
| --- | --- | --- | --- | --- |
| PCM16 | 内置 | 内置 | 已实现 | 可选 |
| IMA ADPCM | 内置 | 内置 | 已实现 | 可选 |
| AAC-LC | 运行时检测 | Media Foundation | 已实现 | 双方检测通过时可选 |
| SBC | 运行时检测 | 未接入 | 未接入 | 显示检测结果，不可选 |
| LDAC | 运行时检测 | 未接入 | 未接入 | 显示检测结果，不可选 |

## 重要边界

Android 系统的 A2DP 编码能力用于手机向蓝牙耳机输出。ListenSphere 使用应用自己的
RFCOMM 数据通道，因此 A2DP 列表中出现 SBC、AAC 或 LDAC，不代表应用能直接取得相应
编码器。界面不会把仅由系统蓝牙栈持有的能力伪装成可用的 ListenSphere 传输格式。

SBC 在多数 Android 设备上属于系统 A2DP 栈能力，并不提供给普通应用作为
`MediaCodec` 编码器；当前只有检测到应用可调用编码器时才会进入能力交集。LDAC 还需要
可分发实现与授权条件，Windows 也没有项目可直接使用的内置 LDAC 解码器，因此两者继续
明确显示为不可选，不以 PCM 冒充对应格式。
