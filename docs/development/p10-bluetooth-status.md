# P10 蓝牙连接与低带宽音频

## 已完成

- 连接类型选定为 Bluetooth Classic RFCOMM，而不是吞吐量不足的 BLE GATT。
- Windows Controller 使用专用服务 UUID
  `d8409f76-1c4f-4d6c-a34b-77d80e71f12a` 发布 RFCOMM 服务。
- Android 使用安全 RFCOMM socket，连接依赖系统蓝牙配对，并由系统建立认证链路。
- Android 12 及以上请求 `BLUETOOTH_CONNECT`（“附近的设备”）权限。
- P10.2 移除未启动扫描时多余的 `cancelDiscovery()`，不再错误要求
  `BLUETOOTH_SCAN` 权限。
- Android 蓝牙页面枚举系统中已配对设备，可以选择电脑并执行双端协议版本握手。
- Windows 与 Android 使用 `LSPB` Magic、主次版本和 UTF-8 Controller 名称完成探测响应。
- Windows 对异常退出后可能残留的 SDP 注册执行有限重试。
- P10.3 将探测连接升级为持久 RFCOMM 会话：手机使用现有设备证书对主控
  指纹签名，双方复用六位验证码和可信设备存储完成首次配对与后续指纹固定。
- 蓝牙音频使用 48 kHz、PCM16、小端、单声道、10 ms 帧；手机在发送前将
  现有 Float32 双声道采集结果下混并量化，码率为 768 kbit/s。
- Windows 将 PCM16 单声道还原为 Float32 双声道，并送入与 Wi-Fi 相同的
  `RemotePcmMixer`，因此音量、静音、电平、断联和删除操作保持一致。
- 蓝牙断线采用与无线网络一致的有限指数退避重连，不会无限快速重试。

## 当前边界

- 当前手机与电脑必须先在系统蓝牙设置中完成配对。
- P10.3 是蓝牙低带宽预览链路，未引入 Opus；音质和多设备并发能力仍低于 Wi-Fi。
- P10.4 将蓝牙载荷升级为逐帧独立的 IMA ADPCM：每个 10 ms 帧从
  960 字节 PCM16 压缩为 244 字节，音频载荷带宽约 195.2 kbit/s；丢失或
  损坏一帧不会污染后续帧的预测状态。
- RFCOMM 音频帧依赖底层安全 RFCOMM 链路，并在应用层验证设备身份与固定
  指纹；首次配对期间仍需用户核对一次性验证码。
- 蓝牙模式尚未实现独立时钟漂移校正和动态码率，长期稳定性需人工验证。

## 人工验收

1. 在 Windows 设置和 Android 设置中先完成电脑与手机的蓝牙配对。
2. 启动 Controller，主界面蓝牙卡片应显示“RFCOMM 探测已开启”。
3. 安装 Android `0.1.9-p10.3`，选择“蓝牙”。
4. 首次使用时允许“附近的设备”权限。
5. 在已配对设备列表中选择电脑，点击“测试蓝牙连接”。
6. 手机应显示“RFCOMM 握手成功”，Controller 蓝牙卡片应显示已验证设备。
7. 在 Controller 生成六位验证码，填入手机后点击“开始发送”。
8. 手机应显示“正在通过蓝牙发送”，Controller 出现远程声道并有电平变化。
9. 验证远程声道音量、静音、断联；重新连接后再验证删除会撤销信任。
10. 连续传输 10 分钟，记录卡顿、延迟累积、断线和自动重连情况。
