# 后续路线：虚拟麦克风与输入路由

## 目标

将手机麦克风或其他远程麦克风从“播放监听音源”扩展为 Windows 应用可选择的
录音输入：

`远程麦克风 → 聆界处理链 → 聆界虚拟麦克风 → 语音、会议或录音应用`

## 功能范围

- 麦克风来源选择、独立音量、静音、电平与混音。
- 默认关闭扬声器监听，开启监听时提示回声和啸叫风险。
- 48 kHz 单声道作为语音默认格式，并保留双声道协商能力。
- 复用噪声门、压缩器和限幅器，后续评估降噪、回声消除及自动增益。
- 多个远程麦克风可混合到同一个虚拟录音端点。
- 权限、录音状态与隐私提示持续可见，不记录原始 PCM。

## 当前状态（阶段 5 验收前）

MVP 已接入：

- Android 无线网络、蓝牙和原生 USB 会明确上报“手机麦克风”来源身份。
- 主控端将麦克风流与普通播放音源分流，默认不送扬声器。
- 主控端可识别并选择 VB-CABLE、VoiceMeeter 等现有虚拟音频端点。
- 支持多个远程麦克风由 Windows 共享模式混合到同一虚拟录音端点。
- 提供虚拟麦克风总音量、总静音和显式监听开关；每个来源仍保留独立音量、
  静音、电平、均衡器、噪声门、压缩器和限幅器。
- 设置已版本化保存；诊断仍不记录 PCM。

尚未实现：

- 自研“聆界虚拟麦克风”驱动、驱动签名与一体化安装。
- 专用 AEC、AI 降噪和自动增益。当前可复用现有噪声门、压缩器与限幅器。

## 实施顺序

1. 新增独立的麦克风输出路由和监听开关。
2. 先适配已有虚拟音频端点，验证 Discord、微信、OBS 和会议软件。
3. 评估并开发“聆界虚拟麦克风”驱动。
4. 完成 Windows 驱动签名、安装、升级、卸载和故障恢复。

## 边界

虚拟麦克风驱动涉及驱动开发、代码签名和发布维护。在驱动与安装链完成前，界面不得
宣称系统中已提供“聆界虚拟麦克风”。阶段 5 以第三方虚拟音频端点完成 MVP 验收；
自研驱动继续作为正式版发布工作。
