# 阶段 2：自动路由与声道管理

## 已完成

- 设置格式升级到版本 8，加入可持久化的自动路由规则与总开关。
- 新的应用声道按以下优先级确定分组：
  1. 当前场景中该声道的精确设置；
  2. 用户为同名来源学习的自动路由规则；
  3. 内置的系统、语音、游戏、媒体来源识别；
  4. 未分组。
- 用户在声道调音面板修改“用途分组”时，自动建立或更新同名来源规则。
- 学习规则默认跨无线网络、蓝牙和有线方式生效；连接方式不会造成同一应用被分到不同用途。
- 分组混音器提供自动路由开关、已学习规则数量和各声道路由来源提示。
- 设置加载会清理无效规则、限制规则数量、去重并规范化优先级。
- 分组弹层展示全部已学习规则，支持单条启停和删除。
- 活动声道支持固定到顶部、同层级上移和下移。
- 固定状态与排序使用稳定声道 ID 保存，重启后恢复。
- 应用流结束或设备断开后立即清理离线应用卡片；布局和路由记忆继续保留。
- 支持将任意活动音源卡片拖到非主 Windows 输出设备，实现一个音源同时播放到多个设备。
- 每条附加输出路由可单独取消，并随设置跨重启保存；切换主输出时会自动暂停重复路由。
- 附加输出采用 WASAPI 共享模式，多个音源进入同一设备时由 Windows 音频引擎混合。

## 人工验收

1. 连接 Sender，并发送至少一个应用声道。
2. 打开该声道调音面板，将用途分组改为“游戏”或“语音”。
3. 确认声道显示“已记住此来源的分组”，分组混音器的规则数量增加。
4. 断开并重新连接 Sender，确认同名应用自动回到刚才选择的分组。
5. 关闭“自动路由”，换一个从未设置过的应用，确认它只采用内置识别，不套用学习规则。
6. 在分组弹层关闭该规则，重新连接应用，确认规则不再生效；重新启用后恢复。
7. 固定一个声道并调整顺序，重启 Controller，确认下一次连接仍按该布局排列。
8. 停止单个应用发送或断开发送端，确认离线应用卡片立即消失。
9. 准备两个 Windows 播放端点，将一个活动音源卡片拖到主输出下方的附加设备卡片。
10. 确认该音源同时从主输出和附加输出发声；点击附加路由右侧移除按钮后只保留主输出。
11. 重启 Controller 并重新连接同一音源，确认附加输出路由自动恢复。
