# 麦克风输出 MVP 验收

## 前置条件

- Windows 已安装 VB-CABLE、VoiceMeeter 或兼容虚拟音频线。
- Windows“播放设备”中能看到对应输入端点，例如 CABLE Input。
- Windows“录音设备”中能看到对应输出端点，例如 CABLE Output。
- Android 使用包含麦克风来源身份支持的最新调试 APK。

## 验收流程

1. 启动 ListenSphere Controller，在“麦克风输出”中选择虚拟音频线的播放端点。
2. 保持“监听到扬声器”关闭。
3. Android 选择“手机麦克风”，分别用无线网络、蓝牙和原生 USB 建立连接。
4. 验证远程设备卡片副标题显示“手机麦克风”，电平随说话变化。
5. 打开 Windows 录音设备电平页，验证虚拟音频线的录音端点有输入。
6. 在 Discord、微信、OBS 或录音软件中选择该录音端点，验证能够录入手机声音。
7. 调节设备卡片音量和静音，确认只影响该手机；调节“麦克风输出”总音量和总静音，
   确认影响全部远程麦克风。
8. 同时连接两台手机麦克风，确认两路都能进入同一虚拟录音端点。
9. 开启“监听到扬声器”，确认麦克风同时从当前 Windows 输出播放；随后关闭，避免回声。
10. 主控端主动断开、手机异常断网以及重新连接各执行 5 次，确认虚拟端点未被长期占用。
11. 重启主控端，确认虚拟端点、总音量、总静音和监听设置能够恢复。

## 通过标准

- 麦克风默认不从扬声器播放。
- 普通手机播放声音仍走原有播放路径，不会进入虚拟麦克风。
- 三种连接方式均能准确识别麦克风来源。
- 多麦克风混合无明显爆音、持续卡顿或资源泄漏。
- 断开后虚拟音频端点可被其他应用正常使用。
- 诊断导出不包含 PCM、证书、密钥或可信设备记录。

## 已知边界

- 当前版本不安装“聆界虚拟麦克风”驱动，依赖用户已有的第三方虚拟音频端点。
- 专用回声消除、AI 降噪和自动增益尚未实现；可先使用声道噪声门、压缩器和限幅器。
- 开启扬声器监听可能产生回声或啸叫，默认必须保持关闭。
