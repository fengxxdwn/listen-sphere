# 阶段 5：Android 三模最终真机验收

## 测试版本

- Android：`0.5.1-stage5`（versionCode 25）。
- Windows Controller：与本次 Release 构建保持一致。
- 覆盖安装必须使用与旧 APK 相同的签名；开发测试使用 Debug APK。

## A. 覆盖安装与配置迁移

1. 在旧版应用中选择蓝牙模式、手机播放声音、AAC-LC 和双声道，并完成一次连接。
2. 记录手动 IP、端口、最近成功连接和蓝牙关联状态。
3. 使用 `adb install -r app-debug.apk` 覆盖安装 versionCode 25，不清除应用数据。
4. 打开应用，确认上述模式、音源、格式、地址、历史和设备关联均保留。
5. 确认可信 Controller 无需重新配对；若主控身份确实改变，则必须拒绝静默信任。

## B. 权限恢复

1. 在系统设置中撤销麦克风、附近设备和通知权限。
2. 返回应用，确认“后台与权限”卡片立即显示对应项目未允许。
3. 点击“打开应用权限设置”，确认进入当前聆界应用详情而非无关设置页。
4. 重新授权并返回，确认状态无需重启即可更新。
5. 永久拒绝权限后重复以上步骤，确认仍可通过系统设置恢复。

## C. 后台与进程回收

1. 开始发送并切换到其他应用，锁屏运行 15 分钟，确认前台服务通知持续存在。
2. 在默认电池优化下记录是否断流；若厂商系统限制后台，点击页面入口调整为不受限制。
3. 再运行 15 分钟，确认状态稳定且电平、帧数继续变化。
4. 使用系统强制停止或 `adb shell am force-stop io.listensphere.mobile` 模拟进程回收。
5. 重新打开应用，确认配置和历史恢复，但不会在用户不知情时自动开启麦克风或录屏。

## D. 三模一致性

对无线网络、蓝牙和原生 USB 分别执行：

1. 连接并持续发送至少 5 分钟。
2. 停止后再次开始，重复 5 次。
3. 由 Controller 主动断开，确认 Android 不自动抢连。
4. 制造一次连接失败，确认只显示中文恢复建议，不出现 socket、堆栈或厂商错误码。
5. 成功连接后确认对应模式成为“最近使用”，其他模式历史仍保留。
6. 从系统设置返回后确认设备、权限和 USB 状态立即刷新。

## E. 格式与声道

1. 蓝牙能力检测后依次验证 PCM16、IMA ADPCM 和设备实际支持的 AAC-LC。
2. 对每种可用编码分别验证单声道和双声道。
3. SBC、LDAC 等应用无法调用或链路未实现的格式必须保持不可选择，并显示原因。
4. 手机和 Controller 能力不相交时不得回退后冒充用户选择的编码。

## 通过标准

- 无闪退、无静默自动录音、无主动断开后的抢连。
- 三模状态、设备身份、历史和错误提示一致。
- 覆盖安装不丢失设置、信任和关联记录。
- 页面不展示技术堆栈、密钥、证书内容或原始 PCM。
- 真机矩阵全部确认后，阶段 5 才标记为人工验收完成。
